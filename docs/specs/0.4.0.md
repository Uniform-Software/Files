# UniFiles 0.4.0 — spécification de développement

> Thème : **« Signer, en local »** : signer des PDF avec un vrai certificat, sans qu'aucun document ne passe par un serveur, et vérifier les signatures reçues.
>
> Statut : à développer · Cible : environ 3 semaines · Version : `0.4.0` (préversions `0.4.0-beta.N`)

Ce document décrit **quoi** construire, **où** dans le code, et **comment vérifier** que c'est fini. Mêmes conventions que la 0.3 : textes dans `Strings.resx` + `Strings.fr.resx`, couleurs et icônes dans `Themes/Tokens.axaml`, originaux jamais modifiés, erreurs rédigées pour l'utilisateur (`ToolException`), toute nouvelle dépendance compatible GPL v3.

> Ce document fixe des choix techniques à partir des textes européens (eIDAS, normes ETSI). Il ne remplace pas un avis juridique : la valeur d'une signature dépend aussi du contexte et du certificat utilisé.

### Hors périmètre (0.4.x / 0.5)

- PAdES **B-LT / B-LTA** : preuves de révocation dans le PDF, validité au-delà de l'expiration du certificat.

- Dialogue **PKCS#11** direct avec les cartes et clés USB, si le système ne les expose pas (voir §14).
- Signature à distance chez un prestataire (Cloud Signature Consortium).
- Signature de **certification** (DocMDP, « modifications autorisées »).
- Formats XAdES, CAdES pour d'autres fichiers que les PDF, et ASiC.

## 2. Étape 0 : résultats du prototype

Prototype réalisé avant la spec (PDFsharp 6.2.4, .NET 10, `System.Security.Cryptography.Pkcs`).

| Question | Résultat | Conséquence |
|---|---|---|
| PDFsharp sait-il signer ? | Oui : `DigitalSignatureHandler.ForDocument(document, signer, options)`, signataire remplaçable (`PdfSharpDefaultSigner`, interface de signataire) | — |
| Le format produit est-il PAdES ? | **Non** : `/SubFilter /adbe.pkcs7.detached`, **aucun attribut signé** (pas de *signing-certificate-v2*), heure de signature en attribut **non signé** | On ne peut pas utiliser la signature PDFsharp telle quelle |
| Une 2e signature garde-t-elle la 1re ? | **Non** : PDFsharp réécrit tout le fichier (un seul `%%EOF`), la plage signée de la 1re signature ne correspond plus → **1re signature cassée** | Il faut écrire nous-mêmes une **mise à jour incrémentale** |
| PDFsharp permet-il l'enregistrement incrémental ? | Non (modes d'ouverture : `Modify`, `Import`, `ReadOnly`, `InformationOnly` ; aucune option d'ajout) | Idem |
| L'apparence par défaut fonctionne-t-elle hors Windows ? | Non : exception « No appropriate font found for family name 'Verdana' » | Résolveur de polices obligatoire (§1 I) |
| .NET produit-il une structure PAdES correcte ? | **Oui** : `SignedCms` + `CmsSigner` (SHA-256, RSA 3072) avec *content-type*, *message-digest* et *signing-certificate-v2* (OID 1.2.840.113549.1.9.16.2.47, encodé avec `AsnWriter`) ; signature vérifiée | La partie cryptographique est entièrement en .NET, sans nouvelle dépendance |

**Décision :** PDFsharp reste la bibliothèque de lecture du PDF et de construction des objets (champ, annotation, apparence). L'écriture de la signature est faite par UniFiles :
- la **sérialisation** des objets passe par l'API publique de PDFsharp (`document.Internals.WriteObject`, `GetAllObjects`) : pas de sérialiseur maison ;
- un **écrivain incrémental** qui ajoute les objets nouveaux ou modifiés à la fin du fichier d'origine, sans toucher un seul octet existant ;
- un **signataire CAdES** .NET.

C'est la même démarche que pour les formulaires en 0.3 (couche `PdfForms` au-dessus de PDFsharp). Pas d'iText.

**Fait (étape 2) :** ajout incrémental sur un PDF à table classique **et** sur un PDF à flux de références (tests automatisés). Reste : ouverture dans Acrobat Reader et passage à l'outil DSS (§13.2).

### Constats pendant le développement

- **Apparences et polices** : `XForm.PdfForm` est interne à PDFsharp et ses polices ne sont finalisées qu'à l'enregistrement complet, incompatible avec l'écriture incrémentale. UniFiles intègre donc lui-même Figtree (`TrueTypeFont` + `PdfFontEmbedder`, police Type0 / Identity-H avec table ToUnicode : texte copiable et cherchable) et écrit ses apparences en flux de contenu.
- **Couverture de Figtree** : tous les alphabets latins de l'UE (seul le `Ţ` à cédille, ancienne graphie roumaine, manque ; `Ț` est présent), mais **ni le grec ni le cyrillique** (langues officielles de l'UE : grec, bulgare). Voir §14.
- **PDFium** ne dessine pas les widgets de formulaire sans son module formulaires : les tests d'apparence aplatissent une copie avant le rendu, et l'écran « Signer » affiche une copie aplatie (valeurs et signatures visibles) pendant que la vraie reste intacte.
- **Numérotation des objets** : en mode `Modify`, PDFsharp compacte et **renumérote** les objets à la lecture ; une mise à jour écrite avec ces numéros pointe vers les mauvais objets dès que le fichier a des numéros libres (cas courant). L'écrivain incrémental ouvre donc en mode `Import`, qui garde les numéros du fichier (test dédié avec objets libres).
- **Filtre des certificats** : en plus de l'usage de clé, les « usages étendus » doivent permettre la signature de documents (signature de documents, e-mail, ou aucun) ; sinon les certificats de développeur Apple ou de serveur apparaîtraient.
- **Import `.p12` sur macOS** : l'option `PersistKeySet` écrit directement dans le trousseau de session ; elle n'est utilisée que sous Windows (test qui vérifie que les tests n'écrivent rien dans le vrai trousseau).

## 4. Identités de signature

Une **identité** = un certificat X.509 **et** l'accès à sa clé privée. UniFiles ne stocke jamais de clé privée ni de mot de passe hors du coffre du système.

### 4.1 Sources

| Source | Comment | Niveau eIDAS visé |
|---|---|---|
| **Certificats du système** | `X509Store(StoreName.My, StoreLocation.CurrentUser)` : trousseau macOS, magasin Windows. Les clés USB et cartes à puce y apparaissent quand leur pilote est installé (CryptoTokenKit sur macOS, minipilote sous Windows) ; **le système demande le code PIN** | Qualifié si certificat qualifié sur dispositif qualifié ; sinon avancé |
| **Fichier `.p12` / `.pfx`** | Import → **ajouté au trousseau / magasin du système** (non exportable), jamais copié ailleurs. Le mot de passe du fichier n'est demandé qu'à l'import | Avancé |
| **Certificat UniFiles personnel** | Créé par UniFiles : RSA 3072, SHA-256, 3 ans, usage « signature numérique » + « non-répudiation », sujet = nom et e-mail saisis. Rangé dans le trousseau / magasin | Simple (identité non vérifiée par un tiers) |
| **Certificat délivré par une autorité d'organisation** (§4.3) | Importé comme un `.p12` | Avancé au sein de l'organisation |

Ne sont proposés que les certificats **valides aujourd'hui**, **avec clé privée** et dont l'usage autorise la signature (`digitalSignature` ou `nonRepudiation`, ou pas d'extension d'usage).

### 4.2 Écran « Identités » (Préférences → nouvelle carte « Signature »)

- Liste : nom, émetteur, date d'expiration, badges **« Clé matérielle »** (clé non exportable sur dispositif), **« Qualifié »** (voir §8.3), **« Créé par UniFiles »**, **« Expire bientôt »** (< 30 jours).
- Boutons : « Importer un fichier .p12… », « Créer mon certificat », « Créer une autorité d'organisation… », « Exporter le certificat public » (`.cer`, pour le transmettre aux destinataires), « Retirer » (pour un certificat créé ou importé par UniFiles seulement ; un certificat du système se retire dans le trousseau).
- Texte d'aide fixe sous « Créer mon certificat » : *« Ce certificat prouve que le document n'a pas été modifié et qu'il a été signé avec cette clé, mais personne n'a vérifié ton identité. Pour une signature reconnue partout en Europe, utilise un certificat d'un prestataire qualifié (clé USB). »*

### 4.3 Autorité d'organisation

Pour une association ou une petite entreprise, sans prestataire ni serveur.

1. « Créer une autorité » : nom de l'organisation → certificat racine (RSA 4096, 10 ans, `basicConstraints CA:true`, `keyCertSign`), clé dans le trousseau / magasin, **non exportable par défaut**.
2. « Délivrer un certificat » : nom + e-mail du membre, mot de passe → fichier `.p12` (3 ans) à lui transmettre, avec un fichier `.cer` de l'autorité.
3. Chaque poste de l'organisation installe une fois le `.cer` de l'autorité (bouton « Faire confiance à cette autorité » dans UniFiles, qui l'ajoute aux autorités de confiance **de l'utilisateur** ; le système demande confirmation).
4. Une liste des certificats délivrés (nom, date, numéro de série) est gardée localement ; la **révocation** est hors périmètre 0.4 (consignée en §14).

### 4.4 Code

`src/UniFiles.Core/Signing/` (nouveau dossier) :
- `SigningIdentity` (record : certificat, source, `IsHardware`, `IsQualified`, `CreatedByUniFiles`).
- `IdentityStore` : énumère, importe, crée, retire ; seul endroit qui touche `X509Store`.
- `CertificateFactory` : certificat personnel, autorité, certificat de membre (`CertificateRequest`).

## 5. Signer un PDF

### 5.1 L'action « Signer un PDF » (`PdfSignTool`, module PDF, `NeedsEditor = true`, un fichier à la fois)

Écran « Signer » (même structure que l'éditeur de formulaire) :

- **Centre** : la page, avec les champs de signature existants en surbrillance (vides : « Cliquer pour signer ici » ; déjà signés : nom du signataire, non cliquables).
- **Placement** : clic sur un champ vide, **ou** tracer un cadre n'importe où (nouveau champ créé), **ou** case « Signature invisible ».
- **Panneau de droite** :
  - Identité (liste du §4, la dernière utilisée présélectionnée) ;
  - Apparence : signature manuscrite (aucune / dessinée / image), afficher le nom, la date, le motif ;
  - Motif (« Lu et approuvé », « Bon pour accord », libre) et lieu (facultatif) ;
  - Horodatage (si activé dans les Préférences, §7) ;
  - Récapitulatif : *« Signé par Élodie Martin · certificat Certigna · valable jusqu'au 12/03/2028 »*.
- **Bouton « Signer »** → la signature est calculée (PIN demandé par le système si besoin) → lot dans la file → `nom - signé.pdf`.

Avant de signer : si le PDF contient des **champs de formulaire non aplatis**, avertir *« Les champs restent modifiables : un changement après signature sera signalé comme modification. Aplatir avant de signer ? »* (Aplatir et signer / Signer quand même).

### 5.2 Signature manuscrite

- **Dessinée** : zone de dessin (souris, trackpad, stylet), tracés lissés, bouton « Effacer ». Enregistrée en vectoriel (liste de tracés, JSON) dans les données de l'appli, pour la réutiliser.
- **Image** : PNG/JPG, fond blanc rendu transparent automatiquement (seuil de luminosité), recadrée sur le contenu.
- Jamais incluse dans un préréglage exporté ni envoyée nulle part.

### 5.3 Apparence (§6.4 pour le format)

```
┌──────────────────────────────────────┐
│  [signature manuscrite]  Signé num.  │
│                          par Élodie  │
│                          Martin      │
│                          15/10/2026  │
│                          Lu et       │
│                          approuvé    │
└──────────────────────────────────────┘
```
Texte en Figtree intégrée, couleur encre `#17140F`, taille ajustée au cadre (minimum 6 pt).

### 5.4 Textes (exemples)

| Clé | Français |
|---|---|
| `Tool_PdfSign_Name` | Signer un PDF |
| `Tool_PdfSign_Description` | Avec ton certificat, sans rien envoyer |
| `Suffix_Signed` | signé |
| `Sign_Invisible` | Signature invisible |
| `Sign_NoIdentity` | Aucun certificat de signature. Crée le tien ou importe un fichier .p12 dans Préférences → Signature. |
| `Error_SignCanceled` | Signature annulée : le code PIN n'a pas été saisi. |
| `Error_CertificateExpired` | Ce certificat a expiré le {0:d}. |

## 6. Format technique : PAdES

### 6.1 Niveau

**PAdES baseline B-B** (ETSI EN 319 142-1), **B-T** quand l'horodatage est activé.

### 6.2 Dictionnaire de signature (`/Type /Sig`)

| Clé | Valeur |
|---|---|
| `/Filter` | `/Adobe.PPKLite` |
| `/SubFilter` | `/ETSI.CAdES.detached` |
| `/ByteRange` | `[0 a b c]` : tout le fichier sauf `/Contents` |
| `/Contents` | CMS en hexadécimal, réservé à **16 384 octets** (32 768 avec horodatage), complété par des zéros |
| `/M` | Date de signature (heure locale avec fuseau) ; **pas** d'attribut *signingTime* dans le CMS (exigence PAdES) |
| `/Reason`, `/Location`, `/Name` | Si renseignés |
| `/Prop_Build` | `<< /App << /Name /UniFiles /REx (0.4.0) >> >>` |

### 6.3 Structure CMS (`CadesSigner`)

- `SignedData`, contenu **détaché**, `IssuerAndSerialNumber`, certificat du signataire + chaîne disponible (sans la racine).
- Empreinte **SHA-256** ; RSA PKCS#1 v1.5 (≥ 2048 bits) ou ECDSA P-256 selon la clé.
- Attributs signés : *content-type*, *message-digest*, ***signing-certificate-v2*** (RFC 5035, empreinte SHA-256 du certificat).
- Attribut non signé (B-T) : *signature-time-stamp* (RFC 3161, §7).
- La clé privée est utilisée via les API du système (`RSA`/`ECDsa` obtenus du certificat) : la clé matérielle ne sort jamais du dispositif.

### 6.4 Objets ajoutés au PDF

- Champ `/FT /Sig` (nom unique « Signature1 », « Signature2 »…) fusionné avec son annotation `/Widget` (`/F 132` : imprimable + verrouillé), ajouté à `/AcroForm /Fields` et aux `/Annots` de la page ; `/SigFlags 3`.
- Apparence `/AP /N` : XObject dessiné avec `XGraphics` (PDFsharp) dans le document ouvert ; polices Figtree **intégrées en sous-ensemble**.
- Signature invisible : `/Rect [0 0 0 0]`, pas d'apparence.
- Remplir un champ de signature **existant** : on lui ajoute `/V` (le dictionnaire de signature) et son apparence ; on ne recrée rien.

### 6.5 Écriture incrémentale (`IncrementalWriter`)

1. Lire le fichier d'origine en octets (inchangé jusqu'au dernier).
2. Ouvrir avec PDFsharp (`Modify`), construire les objets du §6.4, repérer les objets **nouveaux** et **modifiés** (catalogue/AcroForm, page, champ existant).
3. Écrire après le dernier `%%EOF` : ces objets (même numéro et génération pour les modifiés), puis une section de références **du même type que l'original** (table classique, ou flux de références si l'original en utilise un), et un `trailer` avec `/Prev` vers la section précédente et la même `/Root`.
4. Réserver `/Contents` et `/ByteRange` (taille fixe), calculer `ByteRange`, l'écrire, calculer l'empreinte des plages, signer, écrire le CMS en hexadécimal à sa place.

Règles : aucun octet de l'original modifié (test : le préfixe du fichier signé est **identique** à l'original) ; PDF chiffré → `Error_PdfProtected` ; formulaire XFA dynamique → refus (comme en 0.3).

### 6.6 Polices intégrées (§1 I)

- `FigtreeFontResolver` (`IFontResolver` PDFsharp) : sert Figtree Regular / Bold depuis les ressources de `UniFiles.Core` (copie des fichiers de `Assets/Fonts`, licence OFL déjà citée), pour toute famille demandée.
- Assigné une fois au démarrage (`GlobalFontSettings.FontResolver`) et dans les tests.
- Utilisé aussi par `PdfForms` pour l'aplatissement : la limite « caractères hors WinAnsi remplacés par ? » de la 0.3 disparaît (mettre à jour §12 de la spec 0.3).

## 7. Horodatage (option)

- **Préférences → Signature** : « Horodater mes signatures » (désactivé par défaut) + service : liste de services d'horodatage (dont au moins un **qualifié eIDAS**) ou adresse personnalisée.
- Texte sous l'interrupteur : *« Prouve la date de signature. Seule une empreinte du document (32 octets) est envoyée au service choisi, jamais le document lui-même. »*
- Requête RFC 3161 (`Rfc3161TimestampRequest`, .NET) sur l'empreinte de la **valeur de signature**, réponse vérifiée (`ProcessResponse`) puis ajoutée en attribut non signé.
- Échec réseau → message clair et choix : « Signer sans horodatage » / « Annuler ». Jamais de nouvelle tentative silencieuse.
- C'est le **seul accès réseau** ajouté par la 0.4 ; le README et la page « Rien ne quitte ton ordi » le mentionnent.

## 8. Vérifier les signatures

### 8.1 L'action « Vérifier les signatures » (`PdfVerifyTool`, module PDF)

Ne produit pas de fichier : ouvre un **rapport** dans une fenêtre (même composant que les Nouveautés, Markdown), exportable en `.txt`. Accepte plusieurs PDF.

Pour chaque signature, dans l'ordre :

| Ligne | Exemple |
|---|---|
| Statut | ✅ **Signature valide** · ⚠️ **Valide, identité non vérifiée** · ❌ **Document modifié après signature** · ❌ **Signature invalide** |
| Signataire | Élodie Martin (elodie@exemple.fr) |
| Certificat | délivré par Certigna · qualifié · valable du … au … |
| Date | 15/10/2026 14:32 (horodatage de confiance) / (heure de l'ordinateur du signataire) |
| Couverture | « Couvre tout le document » / « Le document a été complété après cette signature (ajouts autorisés : signature suivante) » / « modifié » |
| Format | PAdES B-T (ETSI.CAdES.detached) / ancienne signature Adobe (adbe.pkcs7.detached) |

### 8.2 Procédure (d'après ETSI EN 319 102-1, simplifiée)

1. Intégrité : empreinte des plages `/ByteRange` = *message-digest* ; signature CMS valide (`CheckSignature(verifySignatureOnly: true)`).
2. Couverture : la plage va-t-elle jusqu'à la fin de **sa** révision ? Les révisions suivantes ne contiennent-elles que des ajouts admis (nouvelle signature, horodatage de document, DSS) ? Sinon : « modifié après signature ».
3. Certificat : construction de la chaîne (`X509Chain`) avec les autorités du système + les autorités d'organisation acceptées par l'utilisateur, **sans contrôle de révocation en ligne** par défaut (`X509RevocationMode.NoCheck`) ; option « Vérifier la révocation en ligne » (seul accès réseau, désactivée par défaut).
4. Validité à la date de signature (date d'horodatage si présent, sinon `/M`, présentée comme « déclarée »).
5. *signing-certificate-v2* présent et cohérent (sinon « signature ancienne génération », pas une erreur).

### 8.3 « Qualifié »

En 0.4, hors ligne : badge **« Qualifié (déclaré par le certificat) »** si le certificat porte les *QcStatements* ETSI EN 319 412-5 `QcCompliance` **et** `QcSSCD` (clé sur dispositif qualifié). La confirmation par les listes de confiance européennes est en 0.4.x : le texte dit « déclaré » tant qu'elle n'existe pas.

## 9. Champ de signature dans l'éditeur de formulaire

- Nouveau type dans « Ajouter des champs » : **Signature** (cadre en pointillés, libellé « Signature »).
- Nom unique, case « obligatoire ».
- Le champ est **vide** (`/FT /Sig` sans `/V`) : le destinataire signe avec UniFiles, Acrobat ou un autre outil.
- Aplatir ne supprime **jamais** un champ de signature (ni vide, ni signé) ; aplatir un PDF signé est refusé (`Error_FlattenSigned` : « Ce PDF est signé : l'aplatir casserait la signature. »).

## 10. Intégration : enchaînements, préréglages, dossiers surveillés

- **Enchaînements** : « Signer » ne peut être que la **dernière** étape (`ChainTool.Validate` : nouvelle règle `IsFinalOnly`). Aplatir, remplir, compresser se font avant.
- **Compression après signature** interdite partout : toute action PDF qui reçoit un PDF signé avertit *« Ce PDF est signé : le résultat ne le sera plus »* et nomme le résultat sans « signé ».
- **Préréglages** : enregistrent l'**empreinte du certificat** (SHA-256), l'apparence et le motif ; jamais de mot de passe ni de clé. Si le certificat a disparu : « Certificat introuvable, choisis-en un autre. »
- **Dossiers surveillés** : signer automatiquement est permis **seulement** avec une identité qui ne demande pas d'interaction (clé logicielle du trousseau sans PIN). Clé matérielle → règle refusée à l'enregistrement avec explication. Option affichée en rouge : « Signe tout fichier déposé dans ce dossier ».
- **Historique / Refaire** : la recette contient l'empreinte du certificat ; « Refaire » rouvre l'écran Signer (comme pour les formulaires).

## 11. Sécurité et vie privée

- **Aucun document ne quitte la machine.** Seuls envois possibles, tous optionnels et désactivés par défaut : empreinte pour l'horodatage (§7), numéro de série du certificat pour la vérification de révocation (§8.2).
- Clés privées **uniquement** dans le trousseau / magasin du système ou sur le dispositif matériel ; jamais dans `settings.json`, l'historique, les journaux ni les préréglages.
- Mots de passe `.p12` : utilisés en mémoire pour l'import puis oubliés (`SecureString` non nécessaire, mais jamais journalisés).
- Les journaux d'erreurs (`CrashLog`) ne contiennent ni nom de signataire ni contenu de certificat.
- Signature manuscrite et certificats créés : dans le dossier de données de l'appli, supprimables depuis Préférences → Signature.

### 12.1 `settings.json` (`AppSettings`)

| Clé | Type | Défaut |
|---|---|---|

Pas de migration : clés nouvelles, valeurs par défaut si absentes.

### 12.2 Fichiers

- `<données>/signature/handwritten.json` (tracés) ou `handwritten.png`.
- `<données>/signature/issued.json` (certificats délivrés par une autorité d'organisation : nom, e-mail, numéro de série, dates).

### 12.3 Compatibilité

- Les PDF signés s'ouvrent et se vérifient dans Acrobat Reader, Foxit, Chrome / Edge ; l'Aperçu de macOS les **affiche** mais ne vérifie pas les signatures (à dire dans l'aide).
- Les signatures `adbe.pkcs7.detached` reçues (anciens outils) sont vérifiées et présentées comme « ancienne génération ».

## 14. Risques et décisions ouvertes

| Sujet | Risque | Décision / action |
|---|---|---|
| Écriture incrémentale | PDF exotiques (flux de références, objets compressés, fichiers réparés) | Prototype en début d'étape 2 ; tests sur un corpus (Word, Acrobat, LibreOffice, scanner, PDFsharp) ; en cas d'échec, message clair plutôt qu'un PDF douteux |
| Clés USB sur macOS | Les identités d'un jeton CryptoTokenKit peuvent ne pas apparaître dans `X509Store` de .NET (qui lit les trousseaux classiques) | À vérifier avec une vraie clé dès l'étape 4. Repli : lecture des identités de jeton via `SecItemCopyMatching` (P/Invoke, comme `Trash`/`LoginItem`), ou PKCS#11 en 0.4.x |
| Clés USB sous Windows | Pilote du prestataire absent | Message « Clé non reconnue : installe le logiciel fourni par ton prestataire » |
| Révocation pour l'autorité d'organisation | Un certificat de membre perdu reste valide | Hors périmètre 0.4 ; documenté. 0.4.x : liste de révocation exportée en fichier |
| Valeur juridique | Utilisateur qui croit qu'un certificat auto-signé vaut une signature manuscrite | Badges et textes explicites (§4.2, §8.1) ; jamais le mot « qualifié » sans les QcStatements |
| Grec et cyrillique | Figtree ne les a pas : noms en grec ou en bulgare affichés en carrés dans l'apparence (la signature reste valide, le nom exact est dans le certificat) | 0.4.x : police de secours (Noto Sans, OFL) **avec sous-ensemble** (sinon ≈ 500 Ko par PDF) |
| Taille réservée pour `/Contents` | Chaîne de certificats longue + horodatage dépassant la réserve | Calcul de la taille après une première signature d'essai, réserve = taille × 1,5, plafonnée à 64 Ko |

**Décisions ouvertes à trancher par le produit :**

1. Services d'horodatage proposés dans la liste (au moins un qualifié eIDAS gratuit ou à faible coût) : à choisir.
2. Signature visuelle **sans certificat** (image seule) : proposée comme action à part ou seulement comme apparence ? → proposé : à part, avec le libellé « Apposer une signature (image) » pour ne pas la confondre avec « Signer ».
3. Module : « Signer » dans le module PDF, ou nouveau module « Signature » ? → proposé : module PDF.
4. Icône et couleur de l'écran Signer.
