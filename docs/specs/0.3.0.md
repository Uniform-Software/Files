> Thème : **« UniFiles travaille pour toi »** — automatiser (enchaînements, dossiers surveillés), mieux ranger les résultats, et une première brique de formulaires PDF.
>

## 3. Socle : destinations de sortie

### 3.1 Comportement attendu

Dans l'écran d'action (colonne de droite, au-dessus de « Lancer »), un sélecteur **« Enregistrer dans »** :

| Choix | Résultat pour `~/Photos/Vacances/IMG_1.jpg` |
|---|---|
| **Dossier UniFiles** (défaut, réglage actuel) | `~/Documents/UniFiles/IMG_1.jpg` |
| **À côté des originaux** | `~/Photos/Vacances/IMG_1.jpg` → nom libre : `IMG_1 (2).jpg` (jamais d'écrasement, cf. `OutputFolder.Reserve`) |
| **Sous-dossier daté** | `~/Documents/UniFiles/2026-10-15/IMG_1.jpg` |
| **Choisir…** | Sélecteur de dossier ; le dossier choisi est mémorisé comme dernier choix |

- Le dernier choix est mémorisé **par action** (dans `ToolSettings`, clé réservée `_output`), donc aussi dans les préréglages.
- Une **case « Garder les sous-dossiers »** (visible seulement si des dossiers ont été déposés) reproduit l'arborescence sous la destination : déposer `Vacances/` qui contient `Plage/a.jpg` donne `UniFiles/Vacances/Plage/a.jpg`.
- « À côté des originaux » ignore « Garder les sous-dossiers » (chaque fichier reste dans son dossier).
- Les outils qui combinent (fusion PDF, ZIP, images → PDF, export CSV) écrivent **un** fichier : dans le dossier du **premier** fichier pour « À côté des originaux ».

### 3.2 Code

**Core — nouveau `src/UniFiles.Core/Tools/OutputTarget.cs`**

```csharp
public enum OutputMode { Default, NextToOriginals, DatedSubfolder, Custom }

/// Where each result goes. Replaces the single OutputFolder of a job.
public sealed record OutputTarget(OutputMode Mode, string BaseDirectory, bool KeepTree)
{
    /// Folder for the results of one input. `relativeDirectory` is the input's folder
    /// relative to the dropped root ("Plage"), or "" when it was dropped as a file.
    public OutputFolder For(string input, string relativeDirectory);
}
```

- `DatedSubfolder` : `BaseDirectory/yyyy-MM-dd`.
- `KeepTree` : `Path.Combine(base, rootName, relativeDirectory)`.
- Valider que le chemin final reste **sous** la base (pas de `..`).

**Core — `FileKindDetector.ExpandPaths`** retourne désormais des `InputFile(string Path, string RelativeDirectory)` au lieu de `string`. Garder une surcharge `IReadOnlyList<string>` pour ne pas casser les appelants le temps de la migration.

**Core — `Job` / `JobQueue`**

- `JobQueue.Enqueue(IFileTool, IReadOnlyList<InputFile>, ToolSettings, OutputTarget)`.
- `WorkItem` reçoit son `OutputFolder` calculé à la création ; `ProcessAsync` passe `item.Output` au `ToolContext` au lieu de `job.Output`.
- `Job.Output` est conservé pour l'historique et le bouton « Afficher » : c'est la destination de base.

**App**

- `ActionViewModel` : propriétés `OutputModes`, `SelectedOutputMode`, `CustomOutputDirectory`, `KeepTree`, `HasFolders` ; `CurrentOutputTarget()`.
- `ActionView.axaml` : `ComboBox` + `ToggleSwitch` dans le panneau de droite.
- `FolderIcon.Apply` n'est appelé que pour le dossier UniFiles (inchangé).

**Textes** : `Output_Label`, `Output_Default`, `Output_NextToOriginals`, `Output_Dated`, `Output_Choose`, `Output_KeepTree`, `Output_KeepTreeHint`.

### 3.3 Critères d'acceptation

- [ ] Les 4 modes produisent les chemins du tableau §3.1 (tests unitaires sur `OutputTarget.For`).
- [ ] Un fichier existant n'est jamais écrasé, quel que soit le mode.
- [ ] L'arborescence est reproduite pour un dossier de 3 niveaux.
- [ ] Un préréglage enregistré avec « À côté des originaux » le restitue.
- [ ] Les anciens réglages (sans `_output`) se comportent comme en 0.2 (mode Défaut).

## 4. Enchaînements d'actions

### 4.1 Comportement attendu

- Dans l'écran d'action, sous la liste des actions : bouton **« + Ajouter une étape »**. L'action choisie devient l'étape 1 ; chaque étape a sa carte de réglages repliable (« 1. Redimensionner · 1600 px », « 2. Convertir · WebP 85 % »), réordonnable (flèches ↑ ↓) et supprimable.
- Seules les actions **compatibles avec la sortie de l'étape précédente** sont proposées pour l'étape suivante (ex. après « PDF → images », seules les actions images).
- Actions **interdites dans un enchaînement** : celles qui combinent les fichiers (fusion, ZIP, images → PDF, export CSV) **sauf en dernière étape**, et celles à éditeur (`NeedsEditor` : coupe vidéo, organiser les pages, formulaires).
- **Enregistrer comme préréglage** fonctionne pour un enchaînement ; la pastille porte un badge « 3 étapes » et son infobulle liste les étapes.
- Les fichiers intermédiaires vont dans un dossier temporaire supprimé à la fin ; seul le résultat de la dernière étape est écrit dans la destination (§3).
- File d'attente : un enchaînement = **un** lot, intitulé « Redimensionner → Convertir → Supprimer les métadonnées », progression globale.
- Erreur à l'étape N : le fichier est en échec avec le message « Étape 2 (Convertir) : … » ; les autres fichiers continuent.

### 4.2 Code

**Core — `IFileTool`** : ajouter

```csharp
/// Kind of file produced for an input of the given kind (same kind by default).
FileKind OutputKind(FileKind input);
```

`FileToolBase` : `=> input`. Surcharges : `ImagesToPdfTool` → `Pdf`, `PdfToImagesTool` → `Image`, `AudioExtractTool` → `Audio`, `ZipTool` → `Unknown`, `PdfFormExportTool` → `Unknown`.

**Core — nouveau `src/UniFiles.Core/Tools/ChainTool.cs`**

```csharp
public sealed record ChainStep(IFileTool Tool, ToolSettings Settings);

/// Runs several tools one after the other on each file. Behaves as one IFileTool for the queue.
public sealed class ChainTool(IReadOnlyList<ChainStep> steps) : FileToolBase
{
    public override string Id => "chain";
    public override string Name => string.Join(" → ", steps.Select(s => s.Tool.Name));
    // AcceptedKinds / Accepts = those of the first step.
    // CombinesInputs = last step's (allowed only there).
    // MaxParallelism = min of the steps.
    // ExecuteAsync: for each step, run into a temp OutputFolder; every output of step N is an
    //   input of step N+1 (PDF → images can multiply files); the last step writes to context.Output.
    //   Progress = (stepIndex + stepProgress) / stepCount. Temp folder deleted in finally.
    public static string? Validate(IReadOnlyList<IFileTool> tools); // null when valid, else a user message
}
```

- `KeepsOriginalIfLarger` : appliqué par `JobQueue` sur le résultat final, seulement si **toutes** les étapes le demandent.
- Le `ToolContext.Index` (compteurs de renommage) est celui du fichier d'origine.

**Core — `ToolPreset`** : ajouter `List<PresetStep> Steps` (`ToolId` + `Values`). Un préréglage avec `Steps.Count > 1` est un enchaînement ; `ToolId = "chain"`. Rétrocompatible : `Steps` vide = préréglage 0.2.

**App**

- `ActionViewModel` : `ObservableCollection<StepViewModel> Steps` (chaque étape possède ses `OptionViewModel`), commandes `AddStep`, `RemoveStep`, `MoveStepUp/Down` ; `Launch` construit un `ChainTool` si `Steps.Count > 1`.
- `AppServices.ResolvePreset` reconstruit un `ChainTool`.
- `MacQuickActionsInstaller` / `WindowsContextMenuInstaller` : les préréglages d'enchaînement apparaissent comme les autres (types de fichiers = ceux de la première étape).
- Aperçu avant/après (§0.2) : disponible si toutes les étapes sont des actions images.

**Textes** : `Chain_AddStep`, `Chain_Step` (« Étape {0} »), `Chain_StepError` (« Étape {0} ({1}) : {2} »), `Chain_NotAllowed`, `Chain_Steps` (« {0} étapes »), `Chain_Remove`, `Chain_MoveUp`, `Chain_MoveDown`.

### 4.3 Critères d'acceptation

- [ ] Redimensionner → Convertir WebP → Supprimer les métadonnées : un seul fichier `.webp` par entrée, aux bonnes dimensions, sans EXIF.
- [ ] PDF → images → Compresser : un PDF de 3 pages donne 3 images compressées.
- [ ] Une étape interdite n'est pas proposée ; `ChainTool.Validate` refuse les combinaisons invalides (tests).
- [ ] Aucun fichier temporaire ne reste après succès, échec ou annulation.
- [ ] Un préréglage d'enchaînement se relance depuis l'écran d'action, le clic droit Windows et les Actions rapides du Finder.

## 5. Dossiers surveillés

### 5.1 Comportement attendu

- Nouvelle page **« Automatisations »** dans la barre latérale, entre « Historique » et « Préférences ».
- Une automatisation = **dossier surveillé** + **préréglage** (simple ou enchaînement) + **destination** (§3) + **après traitement** :
  - « Laisser l'original » (défaut) ;
  - « Déplacer l'original dans un sous-dossier *Traités* » ;
  - « Mettre l'original à la corbeille ».
- Carte par automatisation : nom du dossier, préréglage, interrupteur actif/inactif, compteur « 12 fichiers traités aujourd'hui », dernier fichier traité, bouton « Afficher le dossier », supprimer.
- Fonctionne tant que UniFiles tourne (barre des menus / zone de notification). Une préférence **« Lancer UniFiles à l'ouverture de session »** est proposée sur cette page (macOS : élément de connexion ; Windows : clé `HKCU\…\Run`).
- Notification **groupée** : « Captures d'écran : 5 fichiers compressés », au plus une toutes les 30 s par automatisation.

### 5.2 Règles de déclenchement (à respecter strictement)

1. Ne traiter que les fichiers **acceptés** par la première étape du préréglage.
2. Attendre que le fichier soit **stable** : taille inchangée sur 2 relevés à 1 s d'intervalle, et ouvrable en lecture exclusive (Windows).
3. Ignorer : fichiers cachés, temporaires (`.part`, `.crdownload`, `.download`, `.tmp`, `~$*`), et tout ce qui est **sous** le dossier de destination ou le sous-dossier « Traités » (sinon boucle infinie).
4. Ignorer les fichiers produits par UniFiles lui-même (registre en mémoire des chemins écrits par les lots).
5. Au démarrage : **ne pas** retraiter les fichiers déjà présents (seulement les nouveaux) ; un bouton « Traiter les fichiers déjà présents » sur la carte.
6. Regrouper les arrivées proches (2 s) dans un même lot.
7. Dossier introuvable (disque débranché) : carte en erreur « Dossier introuvable », nouvel essai toutes les 30 s.

### 5.3 Code

**Core — `src/UniFiles.Core/Automation/`**

- Corbeille : macOS `NSFileManager trashItemAtURL` (via le même P/Invoke Objective-C que `FolderIcon`), Windows `SHFileOperation` avec `FOF_ALLOWUNDO`. Jamais `File.Delete`.
- Mise en corbeille / déplacement **seulement** si le lot a réussi pour ce fichier.

**App**

- `Services/AutomationService.cs` : crée un `FolderWatcher` par règle active, enfile les lots via `AppServices.Queue`, tient les compteurs, regroupe les notifications.
- `ViewModels/AutomationsViewModel.cs` + `Views/AutomationsView.axaml` ; entrée de navigation dans `MainWindowViewModel.NavItems` (icône à ajouter : `IconAutomation`).
- `Platform/LoginItem.cs` : `IsSupported`, `IsEnabled`, `Enable()`, `Disable()` pour macOS et Windows.

**Textes** : `Nav_Automations`, `Auto_Title`, `Auto_Empty`, `Auto_Add`, `Auto_Folder`, `Auto_Preset`, `Auto_After`, `Auto_AfterKeep`, `Auto_AfterMove`, `Auto_AfterTrash`, `Auto_Today` (« {0} traité(s) aujourd'hui »), `Auto_Missing`, `Auto_ProcessExisting`, `Auto_LoginItem`, `Auto_LoginItemHint`, `Auto_Notification`.

### 5.4 Critères d'acceptation

- [ ] Déposer 10 captures d'écran dans le dossier surveillé → 1 lot, 10 résultats, 1 notification.
- [ ] Un fichier en cours de téléchargement (`.crdownload`, puis renommé) n'est traité qu'une fois, après le renommage.
- [ ] Destination à l'intérieur du dossier surveillé : aucune boucle (test automatisé avec un `FakeTool`).
- [ ] « Corbeille » : l'original est récupérable dans la corbeille du système.
- [ ] Désactiver l'automatisation arrête la surveillance immédiatement ; la réactiver ne retraite pas l'existant.
- [ ] Lancement à l'ouverture de session activable et désactivable sur macOS et Windows.

## 6. Formulaires PDF

### 6.1 Ce qui est livré en 0.3

| Fonction | Où |
|---|---|
| **Remplir** un formulaire existant (texte, case à cocher, bouton radio, liste) | Nouvel éditeur « Remplir le formulaire » |
| **Aplatir** : figer les réponses dans la page, plus de champs modifiables | Case dans l'éditeur + action rapide « Aplatir un formulaire » |
| **Exporter les réponses** de plusieurs PDF en CSV | Action « Exporter les réponses (CSV) » |
| **Ajouter des champs simples** : zone de texte (une ou plusieurs lignes), case à cocher | Mode « Ajouter des champs » de l'éditeur |

Non livré en 0.3 : listes déroulantes et boutons radio **créés** (ils sont seulement remplis), validation, calculs, champs de signature, signature numérique.

### 6.2 Éditeur de formulaire (`PdfFormEditorViewModel`, `NeedsEditor`)

Même structure que l'organiseur de pages (`PdfOrganizerViewModel`) :

- **Colonne gauche** : vignettes des pages (PDFium, `PdfRenderer`).
- **Centre** : la page courante rendue en grand (≈ 1 400 px de haut, zoom 50–200 %), avec un **calque Avalonia** par champ, positionné d'après son rectangle PDF (`/Rect`) converti en pixels :

```
x_px = (x_pt − mediaBox.Left) × scale
y_px = (mediaBox.Top − y_pt_top) × scale      // PDF origin is bottom-left
```
  Tenir compte de `/Rotate` de la page (0/90/180/270) ; test dédié.
- **Mode Remplir** (défaut) : champ texte → `TextBox` superposé ; case → `CheckBox` ; radio → `RadioButton` groupés par nom ; liste → `ComboBox`. Tab / Maj+Tab passent au champ suivant dans l'ordre de la page.
- **Mode Ajouter des champs** : on trace un rectangle à la souris → panneau latéral : type (texte / texte multiligne / case), nom (unique, généré « champ_1 » par défaut), obligatoire, valeur par défaut, taille de police (auto ou 8–24 pt). Déplacer / redimensionner par poignées ; Suppr pour retirer un champ **ajouté** (les champs d'origine ne sont pas supprimables en 0.3).
- **Bas de l'écran** : « 8 champs · 5 remplis », case **« Aplatir (figer les réponses) »**, bouton **« Enregistrer le PDF »** → lot dans la file (sortie : `nom - rempli.pdf`).
- Un PDF **sans champs** ouvre directement le mode « Ajouter des champs », avec un message d'aide.
- PDF protégé par mot de passe : message `Error_PdfProtected` (existant).

## 7. Nouvelles actions

Toutes héritent de `FileToolBase`, sont enregistrées dans `ToolCatalog`, ont leurs textes dans les deux `.resx` et au moins un test.

### 7.1 F — PDF → images (`PdfToImagesTool`, module PDF)

- Options : format (PNG, JPG), résolution (72, 150 par défaut, 300 dpi), pages (toutes / plages, même syntaxe que « Découper »).
- Une image par page : `nom - page 01.png` (numéro sur 2 chiffres, 3 au-delà de 99 pages), dans un sous-dossier `nom/` si plus de 1 page.
- Rendu : `PdfRenderer.Render` avec une taille dérivée du DPI (`largeur_pt × dpi / 72`) ; ajouter une surcharge `Render(page, double scale)`.
- `OutputKind(Pdf) = Image`. `ShowsSizeChange = false`.

### 7.2 G — Supprimer les métadonnées d'un PDF (`PdfStripMetadataTool`)

- Vide `Info` (Title, Author, Subject, Keywords, Creator, Producer, dates), supprime le flux `/Metadata` XMP du catalogue et des pages.
- Option « Garder le titre » (désactivée par défaut).
- Test : un PDF avec auteur et XMP n'en contient plus aucune trace (recherche de chaîne dans le fichier).

### 7.3 H — Normaliser le volume (`AudioNormalizeTool`, module Vidéo / audio)

- Accepte vidéo et audio ; la vidéo est copiée sans réencodage (`-c:v copy`).
- Cible : « Podcast et voix (−16 LUFS) » (défaut), « Musique et streaming (−14 LUFS) », « Diffusion (−23 LUFS) ».
- ffmpeg `loudnorm` en **deux passes** : passe 1 `-af loudnorm=I=…:TP=-1.5:LRA=11:print_format=json -f null`, lire le JSON dans la sortie d'erreur, passe 2 avec `measured_*` et `linear=true`.
- Test : un sinus à −30 LUFS ressort à la cible ±1 LU (mesure par une 3ᵉ passe `ebur128`).

### 7.4 I — Couper le son (`VideoMuteTool`)

- `-map 0 -map -0:a -c copy` (instantané, aucune perte). Sortie : `nom - muet.ext`.

### 7.5 J — Créer une archive ZIP (`ZipTool`, nouveau module **Fichiers**)

- Nouveau `ToolModule.Files` (couleur et icône à ajouter dans `Tokens.axaml` et `ModuleInfo`) ; accepte **tous** les fichiers (`AcceptedKinds` vide).
- `CombinesInputs = true`, `MinimumInputs = 1`. Nom : nom du dossier déposé, sinon `UniFiles AAAA-MM-JJ.zip`.
- Conserve l'arborescence relative (§3, `InputFile.RelativeDirectory`) dans l'archive.
- Option niveau : « Rapide », « Équilibré » (défaut), « Le plus petit » (`CompressionLevel`).
- `System.IO.Compression` ; noms d'entrées en UTF-8 (accents corrects sur Mac et Windows).

## 12. Risques et décisions ouvertes

| Sujet | Risque | Décision / action |
|---|---|---|
| Bibliothèque formulaires | PDFsharp ne gère pas bien les apparences ou l'aplatissement | Prototype §6.7 en premier ; repli iText (AGPL v3). **Résultat : PDFsharp conservé** pour lire et écrire le PDF, mais avec notre propre couche AcroForm (`PdfForms`) : les apparences des champs (texte, cases, radios) et l'aplatissement sont écrits par UniFiles, PDFsharp ne sachant ni cocher une case sans apparence existante ni vraiment aplatir. Pas d'iText. |
| Polices PDFsharp hors Windows | Exceptions « no font resolver » | **Sans objet** : les apparences utilisent la police standard Helvetica (WinAnsi, métriques intégrées), non embarquée, donc aucun résolveur de polices n'est appelé. Les caractères hors WinAnsi sont remplacés à l'affichage aplati ; la valeur du champ reste exacte. |
| `FileSystemWatcher` | Événements manqués (réseau, iCloud, OneDrive) | Passe de vérification toutes les 30 s (§5.3) |
| Boucles des dossiers surveillés | Traiter ses propres résultats | Règles §5.2-3 et 4, test automatisé |
| Corbeille | Suppression définitive par erreur | Uniquement via les API de corbeille du système ; jamais `File.Delete` sur un original |
| Arborescence | Chemins trop longs sous Windows (> 260 caractères) | `longPathAware` activé dans `app.manifest` ; message clair sinon |
| Enchaînements multiplicateurs | PDF de 500 pages → 500 images × étapes | Progression par fichier, annulation testée, temporaire nettoyé |
| Compatibilité des réglages | Préréglages 0.2 perdus | Tests de migration (§10) |

**Décisions ouvertes à trancher par le produit :**

1. Séparateur CSV par défaut : `;` (Excel FR) ou `,` ? → **retenu : selon la langue de l'interface** (`;` en français), modifiable dans l'action.
2. Couleur et icône du nouveau module **Fichiers** (ZIP) : **provisoire** : rose `#FF7AB6` et icône d'archive ; à redessiner.
3. Automatisations : limiter à 10 dossiers surveillés en 0.3 ? → **retenu : oui** (`WatchRule.MaximumCount`).
